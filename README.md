# Instant Landing Page

A standalone web app (NuroWorks): describe your business, get a full landing page generated by Claude, see a locked preview (hero only), pay via Stripe to unlock and download the complete HTML file.

## How the paywall actually works (read this first)

The free preview **only ever contains the hero section**. The rest of the page (value props, testimonials, features, footer) is generated by Claude but is **never sent to the browser** until the server confirms payment. This is enforced server-side — the "locked" section shown in the preview is fake placeholder markup built by our own code, not real content with CSS blur applied. Viewing page source or opening dev tools before paying reveals nothing beyond the hero. Only `GET /api/download/:id`, which checks `paid: true` in the server-side store first, ever returns the full page.

## File Structure

```
index.js            Express server — all routes
claude.js            Claude wrapper: generates the page, splits hero/rest via HTML comment markers
pageBuilder.js        Assembles the locked preview doc and the full paid doc
stripe.js             Stripe wrapper: checkout session creation, webhook verification
store.js               In-memory store: generation id -> { html, paid status }
utils/logger.js         Structured logger
public/
  index.html            The input form
  preview.html           Renders the locked preview in an iframe, has the Unlock button
  success.html            Confirms payment, shows the download link
  style.css              Shared site styling (not the generated pages themselves)
.env
package.json
```

## Stripe webhook setup (required — don't skip this)

The webhook is what durably confirms payment even if someone closes their browser right after paying (the success-page fallback check only covers the case where they land back on your site).

1. Deploy this app first so you have a real `PUBLIC_URL`.
2. Go to the [Stripe Dashboard → Developers → Webhooks](https://dashboard.stripe.com/webhooks) → **Add endpoint**.
3. Endpoint URL: `https://your-service.onrender.com/webhook/stripe`
4. Select the event `checkout.session.completed`.
5. After creating it, Stripe shows a **Signing secret** (starts with `whsec_`) — copy that into `STRIPE_WEBHOOK_SECRET` in your Render environment variables.
6. Redeploy after adding the env var so it picks up the new secret.

Use Stripe's **test mode** keys and test card `4242 4242 4242 4242` (any future expiry, any CVC) to verify the full flow before switching to live keys.

## How It Works

1. User describes their business on `index.html` → `POST /api/generate`.
2. `claude.js` generates a full landing page, with the hero section and the rest of the page wrapped in required HTML comment markers (`<!-- HERO_START -->` etc.) so they can be reliably split apart.
3. `pageBuilder.js` builds two documents: a `previewHtml` (real hero + fake locked placeholder) and a `fullHtml` (real hero + real rest). Both get stored server-side in `store.js`, keyed by a generation id. Only `previewHtml` is ever sent to the browser at this point.
4. User clicks "Unlock" on `preview.html` → `POST /api/checkout` creates a Stripe Checkout Session and redirects the browser to Stripe.
5. On successful payment, **two things happen in parallel**: Stripe redirects the browser back to `success.html`, and Stripe also calls `POST /webhook/stripe` in the background. Either one can mark the generation as paid — the webhook is the durable source of truth, and the success-page check (`GET /api/verify/:sessionId`) is a fast-path so the user doesn't have to wait on webhook delivery.
6. Once `paid: true`, `GET /api/download/:id` serves the full HTML file as a download.

## Notes on Production Hardening

- **Generation store** (`store.js`) is an in-memory `Map`. It resets on restart and won't work across multiple server instances — swap for Redis or a database table before scaling beyond one Render instance. It also auto-prunes entries older than 24 hours; adjust `MAX_AGE_MS` if you want generations to stay downloadable longer.
- **Rate limiting**: there's currently no limit on how often someone can call `/api/generate`, which calls the Claude API (real cost) for every request. Add per-IP throttling before this gets meaningful traffic.
- **Webhook security**: the webhook route already verifies Stripe's signature (`stripe.webhooks.constructEvent`) — don't remove that check or bypass it, it's what stops anyone from POSTing a fake "payment succeeded" event directly to your server.
- **Live mode**: switch `STRIPE_SECRET_KEY` to a live key (`sk_live_...`) and re-register the webhook endpoint for live mode (test-mode and live-mode webhooks are separate in Stripe) when you're ready to accept real payments.
